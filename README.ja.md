# mermaid-design

[English](README.md) | 日本語

設計意図を伝えるMermaid図を作り、同じ原稿からSVG・PNGへ出力するエージェント用スキルです。フローチャート、システム構成、状態、時系列、データ関係を扱います。

エージェントは、構文が正しいか、画像を読み取れるか、原資料の事実と一致するかを確認します。ローカルのツールが配置候補、図形の診断、確認画像、ハッシュを生成し、意味と見た目はエージェントが確認します。

## 導入

Node.js 20以降とChromiumブラウザを用意してください。リポジトリ全体をエージェントのスキルディレクトリへ`mermaid-design`として配置するか、[SKILL.md](SKILL.md)を読み込むよう設定します。スクリプトとpackageファイルも同じ場所に置きます。

リポジトリのディレクトリで実行します。

```sh
npm run setup
npm exec --prefix .runtime -- playwright install chromium
```

固定した依存関係を`.runtime/`へ導入します。Chromiumが導入済みなら2行目は不要です。実行ファイルを`--browser`または環境変数`MERMAID_BROWSER`で指定できます。

描画にはMermaid 11.12.0とPlaywright 1.62.1を使用します。以下の測定はmacOS上のNode.js 24.13.1で行いました。

## 使い方

ファイル読取・シェル実行・画像確認ができるエージェントへ依頼します。

> mermaid-designを使い、渡した事実を図にしてください。Mermaid原稿、SVG、PNG、意味と読みやすさについての短い確認記録を納品してください。

新規作成と既存図の変更に使えます。エージェントがスキルを読み、図式を選び、実際に描画した画像を見て、原資料との一致を確認します。

描画ツールは直接実行することもできます。

```sh
node scripts/diagram.cjs review docs/architecture.mmd --out-dir output --improve
node scripts/diagram.cjs verify output/architecture.render.json
```

`review --improve`は3種類の配置設定を比較し、選んだSVG、PNG、閲覧幅の確認画像、`.render.json`を出力します。大きな図は全体画像と重なりのある詳細画像に分かれる場合があります。`verify`は記録された原稿・生成物のハッシュを照合し、保存済みの環境と設定ハッシュを返します。再描画や意味・見た目の合格判定は行いません。

方向が意味を持たない新規フローチャートでは、`drafts --presentation-only`で元原稿を変更せずにLR・TB・BTの候補を作れます。画像を確認してから候補を選びます。具体的な操作と確認要件は[スキル](SKILL.md)を参照してください。

## アーキテクチャ

![原資料から描画と確認を経て成果物を作る流れ](docs/architecture.svg)

| 構成要素 | 機能 |
| --- | --- |
| `SKILL.md` | 関係・境界・図式・確認についてのエージェント向け指示 |
| `scripts/diagram.cjs` | 原稿候補、一括描画、出力、ハッシュ照合 |
| `scripts/audit.cjs` | ブラウザ内での図形診断 |
| `scripts/setup.cjs`、`scripts/runtime.cjs` | 固定依存関係の導入と読込 |
| `.mmd`、`.svg`、`.png`、`.render.json` | 原稿、画像、生成元の記録 |

描画はローカルで実行し、ブラウザのネットワーク要求を遮断します。原稿を変えた図は生成物を作り直します。確認記録を引き継げるのは、事実・原稿・環境・設定・生成物が一致する場合です。意味・見た目の自動承認フラグは`false`のままにし、実施した確認を別の記録へ残します。

## 定量比較

2026年10月23日に、同じ3つの架空の例題を、それぞれ新しいエージェントの文脈で測定しました。スキルなし側は通常のMermaid知識と単純な描画ヘルパーを使い、あり側はこの英語版スキルとCLIを使いました。モデル、依存関係、ブラウザ、例題の事実、納品要件、画像確認の機能は共通です。

| 例題 | なし：トークン | あり：トークン | なし：秒 | あり：秒 |
| --- | ---: | ---: | ---: | ---: |
| 構成フロー | 1,027,142 | 242,832 | 231.6 | 110.0 |
| 取得の時系列 | 350,107 | 177,551 | 68.4 | 60.0 |
| 独立した属性 | 462,549 | 277,609 | 109.8 | 85.4 |

3例題の合計は、実トークン数が1,839,798から697,992へ62.1%減、実行時間が409.8秒から255.3秒へ37.7%減でした。モデルからのツール呼出しは36回から12回になりました。

手法名を伏せた独立レビューでは、スキルあり側の3成果物はすべて構文・視覚・意味の各項目で4/4でした。対応するスキルなし側より下がった得点はありません。なし側の構成フローは線が境界名を横切ったため視覚が3/4で、ほかの項目と残る2成果物は4/4でした。

トークン数は実行環境が報告した入力と出力の合計で、キャッシュ入力を含みます。キャッシュ入力は入力の内数です。時間はツールの待ち時間を含む各試行の実行時間です。導入、進行管理、独立採点、試行間の待ち時間は含みません。6試行すべて中断なく完了しました。

なし側の最初の構成フローには、試行手順を確認する短い待ち時間が含まれ、そのまま時間へ計上しています。1つのモデル・実行環境で3例題を各手法1回ずつ測った結果であり、一般的な高速化率や人による品質同等性を保証するものではありません。

[測定方法・例題・集計値・品質得点・成果物](benchmarks/README.md)を同梱しています。表の合計値は次のコマンドで再計算できます。

```sh
node benchmarks/summarize.cjs
```

## テスト

開発時は通常のnpm配置へ依存関係を導入します。

```sh
npm ci --ignore-scripts
npx playwright install chromium
npm test
```

5図種別の7例題を使い、原稿保持、不正入力、生成物の改ざん、古い出力、図形の問題、PNGの網羅性と一致を検証します。公開版の検証では詳細PNGを17枚生成しました。`npm run test:drafts`はブラウザを起動せず、原稿候補に関する16項目を検証します。
